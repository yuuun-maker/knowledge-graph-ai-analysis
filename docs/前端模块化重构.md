# 教师端 / 学生端前端模块化重构说明

> 范围：仅重构 `frontend-vue/` 的教师端与学生端页面，不改后端、数据库、接口路径/参数/响应格式，不改变路由懒加载与页面视觉。

## 1. 目标与结果概览

原先两个单文件 SFC 同时承载页面框架、所有业务 Tab、弹窗、表单、请求和样式：

| 文件 | 重构前 | 重构后（页面入口） |
|---|---:|---:|
| `src/views/TeacherView.vue` | 4531 行 | 530 行 |
| `src/views/StudentView.vue` | 4048 行 | 408 行 |

页面入口现在只保留：整体布局、Tab 选择、课程/文档上下文、路由同步、跨 Tab 协调与全局弹窗；具体业务下沉到 Tab 组件和 composables。

新增/修改的模块总计约 1 万行（含从原文件拆出的 scoped 样式、注释与回归测试），不是把代码删减掉，而是按职责重新组织。

## 4. 状态与通信

- **页面级共享状态**：教师端的课程/文档上下文、文档列表、批改角标；学生端的学习上下文、图谱/进度/推荐、掌握与收藏缓存、详情抽屉。其余状态都留在各自 Tab 内。
- **Props 向下、Emits 向上**：Tab 组件不直接改父级数据。教师端课程选择统一 `update:courseId`，文档选择 `update:documentId`，切换文档 `switch-document`；学生端 `locate` / `view-focus` / `toggle-favorite` / `highlight-path` 等均为显式事件。
- **Pinia**：没有新增全局状态。唯一改动是 `store.fetchDocuments` 增加请求序号与当前课程校验，防止旧课程慢响应覆盖新课程文档列表（状态语义不变）。
- **KeepAlive**：未引入。`el-tab-pane` 原本就会保留已挂载的 Tab，拆分后行为一致；没有改变缓存、刷新、状态保留语义。

## 5. 竞态、重复请求与生命周期修复

统一工具：`useLatestRequest`（请求序号 + 组件卸载后失效）。所有列表型读请求都接了它；写操作不使用取消语义。

| 问题 | 处理 |
|---|---|
| 快速切课，旧文档列表覆盖新课程 | `useDocumentList` 按课程校验 + 请求序号；同课程并发请求合并；用户刷新可打断静默轮询 |
| `open=1` 深链自动选首文档失败 | 课程 watch 与 `open` watcher 共用同一个在途请求，不再互相作废；已补 Playwright 回归 |
| 静默轮询与用户刷新互相作废 | 前台刷新用 `force` 发新请求，静默/首屏请求复用同一 Promise |
| 教师题库：快速切换题目筛选/分页 | 列表、总览、覆盖率分别带请求序号；切课后作废旧响应 |
| 教师题库知识点下拉永久缓存导致名称过期 | 去掉长期缓存，改为「每次进入题库重取、仅合并并发请求」 |
| 教师监测/批改/题库：课程清空或切课 loading 卡死 | 切课/清空时显式复位 loading，并作废在途请求 |
| 学生图谱请求成功但推荐请求失败时整页归零 | 推荐请求独立 catch，只清推荐相关状态；图谱/进度保留 |
| 收藏夹被推荐接口阻塞 | 新增 `graphDataChecked`，收藏夹只依赖「图谱 + 收藏列表」，不再等推荐 |
| 学生路径工具结果跨文档残留 | `ctxKey` 变化时清空推荐/目标路径/前置结果并作废在途请求；响应同时校验上下文 |
| 做题练习旧上下文响应写入新页面 | 统计/错题/收藏题目请求随上下文失效并校验 `ctxKey`；提交答案仍完成写入，但不把结果挂到新上下文 |
| 题目收藏连续点击重复写入 | 同一 `question_id` 在途时忽略重复点击 |
| 学生文档列表跨来源竞写 | 统一走 `store.fetchDocuments`（内部请求序号 + 当前课程校验） |
| 智能问答切换资料后旧回答迟到 | 切换 `ctxKey` 时作废在途问答并解除输入锁定（历史消息保留） |
| 教师切回图谱 Tab 抽屉残留 / 编辑列表不刷新 | 图谱 Tab 接收 `active`，重新进入时收起抽屉，编辑模式重载知识点 |
| 教师从题库点「待批改」沿用旧页码 | 批改组件暴露 `resetForDirectEntry()`，跳转前回到第 1 页 |
| ECharts 重复 init / resize 监听泄漏 | `useEChart` 统一管理 init/setOption/resize/dispose，卸载移除监听 |
| 文档轮询在离开页面后继续跑 | `useCourseDocuments` 在 Tab 失活/无在途任务/卸载时停止 timer |
| G6 实例 | 复用现有 `GraphCanvas`，未重写；组件卸载仍由它内部销毁，教师三栏的 `:key` 语义保留 |

### 顺带修复的原有 Bug（与重构引入的问题分开记录）

1. **批改 Tab 从侧栏直达时不加载数据**：原 `activeTab` watcher 遗漏了 `grading`，只能手动点「刷新」。现在进入 Tab 会加载汇总与列表。
2. **学生管理页切换课程会把用户带到课程文档 Tab**：原实现复用了 `syncDocumentsRoute`（固定 `tab=documents`）。现在统一按当前 Tab 写路由。
3. **学生端推荐接口失败会连带清空已取回的图谱**：导致总览/收藏显示 0。已拆开错误边界。
4. **学生端切换文档后详情抽屉/路径分析结果仍停留在上一文档**：已在新上下文切换时收起并清空。

## 7. 尚未解决的问题与风险

1. **未接 AbortController**：旧请求只是结果被丢弃，网络请求仍会完成；与现有 axios 封装保持一致。若后续需要真正取消，可在 `request.js` 统一透传 `signal`。
2. **问答历史不按上下文分组**：切换资料后历史消息保留（原行为），只作废在途回答；相关知识点左栏仍可能显示历史消息的来源。若要彻底隔离，需要产品层决定「切换即清空」还是「按资料分组」。
3. **批改后题库统计不跨 Tab 立即刷新**：当前切回题库会重新加载（用户可见结果一致）；未额外引入跨 Tab 事件总线。
4. **`StudentPathTab.vue` 仍是最大的 Tab 组件（约 763 行，含样式）**：路径工具三块可再抽成独立组件；本次优先保证行为等价，未继续细分。
5. **上传 / 图谱编辑 / 批改写操作未做自动化 e2e**：这些操作会写线上 SQLite/Neo4j，本次仅做代码审查与只读回归；运行写操作测试前需按 `docs/评测运行简明教程.md` 使用专用库。
6. **E2E 冒烟依赖演示数据**（admin / demo_student 及至少一门有知识点的课程），与现有 `regression.spec.ts` 的数据假设一致；未纳入 CI。
