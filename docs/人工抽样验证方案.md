# 知识抽取人工抽样验证方案

> 对应 A10 赛题硬性指标：**「知识抽取的准确率（人工抽样验证）不低于 70%」**。
>
> 本方案定义该指标的**口径、抽样方法、判定标准与计算公式**，配套两个脚本：
> `backend/scripts/sample_for_manual_check.py`（抽样）与
> `backend/scripts/calc_manual_accuracy.py`（汇总）。
>
> **当前状态：方法与工具已就绪，判定结果待人工填写后生成**（结果表见第五节）。

---

## 一、为什么这套东西之前不存在

本项目此前申报的抽取指标，全部来自 `backend/eval_accuracy.py` 对**冻结人工金标准**的自动评测
（开发集第 7 章·树：关系 F1 = 0.8312）。那套评测更严格、更细粒度，但**与赛题口径不是一回事**：

| | 自动评测（已有） | 人工抽样验证（本方案） |
|---|---|---|
| 评判依据 | 与另一份人工标注的 Gold 比对 | 评判者**直接看原文**判断这条知识对不对 |
| 度量 | P / R / F1（能同时反映漏抽） | **准确率 = 正确条数 / 判定条数（即 Precision）** |
| 决定结果的因素 | 模型能力 + Gold 的标注口径 | 模型能力 + 评判者对原文的理解 |
| 赛题口径 | 否 | **是** |

两者不能互相替代，因此**必须都做、都必须报**：

- 只看自动评测 → 口径不对，评委可判定「未提供赛题要求的指标」；
- 只看人工抽样 → **抽样天然测不出召回**（抽不到「系统漏了什么」），会掩盖漏抽问题。

## 二、抽样母本

抽样母本选用**三章封存集**的系统预测输出（`backend/eval_data/pred_*_v15.json`，取第 1 轮）：

| 章节 | 来源 | 规模 | 预测产出（第 1 轮） |
|---|---|---|---|
| 物理·第 2 章 运动学 | OpenStax College Physics 2e（中文翻译版，CC BY 4.0） | 36,647 字符 | 46 实体 / 54 关系 |
| 数据结构·第 2 章 复杂度分析 | Hello 算法（krahets/hello-algo，CC BY-NC-SA 4.0） | 16,410 字符 | 38 实体 / 41 关系 |
| 化学·第 2 章 原子分子与离子 | OpenStax Chemistry 2e（中文翻译版，CC BY 4.0） | 40,078 字符 | 68 实体 / 62 关系 |

**为什么用封存集而不是开发集**：这三章的文本**从未参与过提示词迭代**（提示词全部在
《Hello 算法》第 7 章「树」上开发），因此抽样结果更接近系统面对陌生教材时的真实表现。
用开发集抽样的分数会系统性偏高。

去重后关系池共 **156 条**、实体池共 **154 个**。

## 三、抽样设计

### 3.1 分层，而非简单随机

四类关系的产出量极不均衡（关系池：CONTAINS 98 / RELATED_TO 40 / APPLIES_TO 16 / PRECEDES 2）。
简单随机抽样会让 CONTAINS 占据绝大多数样本，APPLIES_TO 与 PRECEDES 的准确率**无从估计**。

因此采用**分层抽样**：

1. 每种关系类型先保底抽 `--min-per-type` 条（默认 10 条；池子不足则全取）；
2. 剩余名额按各类型**剩余池子大小**比例分配。

实体按 `category`（概念 / 定理 / 公式 / 方法）分层，保底 5 条。

### 3.2 样本量

| 对象 | 样本量 | 理由 |
|---|---:|---|
| 关系 | **100 条** | 样本量 100 时，Wilson 95% 置信区间半宽约 ±9%。这是能在「评审可信」与「人工工作量可承受」之间取得平衡的量级——判定 100 条约需 2~3 小时 |
| 实体 | **50 个** | 实体判定比关系简单（看名称与类别是否成立），50 个即可达到 ±13% 的精度 |

本方案默认抽 100 + 50。若时间允许，建议**把关系样本扩到 156 条（全量判定）**——
全量判定可以顺带得到一份完整的人工 Precision，且不受抽样误差影响。

### 3.3 可复现

抽样使用固定随机种子（默认 `20261008`）。同一批预测文件 + 同一个种子，
必然抽出**完全相同**的样本，评审可自行重跑复核：

```bash
cd backend
python scripts/sample_for_manual_check.py            # 默认 seed=20261008，抽 100 关系 + 50 实体
```

产出落在 `backend/eval_data/manual_check/`：

| 文件 | 用途 |
|---|---|
| `抽样判定表_关系.csv` | **交给判定者填「判定」列**（utf-8-sig，Excel 直接打开不乱码） |
| `抽样判定表_实体.csv` | 同上 |
| `抽样对照.md` | 人读版：每条样本 + 模型给出的证据 + 自动定位的原文上下文 |
| `抽样元信息.json` | 抽样参数、各类型池子大小与配额，供评审复核 |

## 四、判定标准

**判定者只看两样东西：原始课程文本、系统输出。不得打开同目录下的 Gold 文件。**
若打开 Gold 再判，判定会向标注者偏移，抽样就失去了独立验证的意义。

### 4.1 关系判定

对每条抽样关系 `source —类型→ target`，回答一个问题：

> **只看原文，这条关系成立吗？类型和方向对吗？**

| 判定 | 含义 |
|---|---|
| **正确** | 原文支持该关系，且**类型与方向都对** |
| 错误-臆造 | 原文没有支持该关系的依据（模型自行推断或编造） |
| 错误-方向反 | 关系类型对，但 source 与 target 写反了（如「AVL 树 CONTAINS 二叉搜索树」） |
| 错误-类型错 | 两个知识点之间确有关系，但类型选错（如把包含关系写成前置关系） |
| 错误-端点不成立 | source 或 target 本身不是一个成立的知识点（名字错、粒度错、压根不是知识点） |

**只有「正确」计入分子。** 「两个知识点确实有关但类型错了」算错误——赛题测的是
知识抽取的整体质量，类型与方向是抽取结果的组成部分。

### 4.2 实体判定

| 判定 | 含义 |
|---|---|
| **正确** | 原文中确实存在该知识点，名称规范、类别恰当 |
| 错误-臆造 | 原文中不存在该"知识点" |
| 错误-粒度不当 | 确实是知识点，但拆得过细或过于笼统 |
| 错误-类别错 | 实体成立，但 category 归错（如把"方法"标成"概念"） |

### 4.3 判定纪律

1. **不看 Gold**（见上）。
2. **不看别人已判的结果**，避免相互锚定。若有多人判定，各自独立完成后比对。
3. **不确定的条目不要硬判**：在「备注」列写「不确定 + 理由」，判定列留空。留空项**不计入分母**，但会在汇总报告里单独披露条数——不得静默丢弃。
4. **证据列只作参考**：`抽样对照.md` 会自动按模型给出的 evidence 在原文中定位上下文。定位不到时标 ⚠，这本身是「证据不实」的信号，但**判定依据始终是原文本身**，不是模型给的证据。

## 五、准确率计算

### 5.1 公式

```
人工抽样准确率 = 判定为「正确」的条数 / 已完成判定的条数
```

这是 **Precision（查准率）**。符号说明与理由见第一节。

### 5.2 置信区间

同时给出 **Wilson 95% 置信区间**（比正态近似在 p 接近 0/1 或 n 小时更稳定）：

```
center = (p + z²/2n) / (1 + z²/n)
half   = z/(1 + z²/n) · √( p(1-p)/n + z²/4n² )      z = 1.96
```

### 5.3 达标判定采用区间下界

**只有当置信区间下界 ≥ 0.70 时，才可以写「满足赛题准确率要求 ≥70%」。**

若点估计 ≥ 0.70 而区间下界 < 0.70，正确写法是：

> 点估计 0.7X，95% CI [a, b]，样本量不足以断言达标，需扩大样本。

反之，若点估计 < 0.70，则**如实报告未达标**，并在报告中给出错误构成分析（哪类错误最多、
是否与某类关系的判定规则有关），以及后续改进方向。**不得只报点估计、不报区间。**

### 5.4 汇总

```bash
cd backend
python scripts/calc_manual_accuracy.py
```

产出 `backend/eval_data/manual_accuracy.json` 与 `manual_accuracy.md`，含：
总体准确率与置信区间、**按关系类型分层的准确率**、**按章节分层的准确率**、错误构成、
未判定条数，以及达标结论。

## 七、与自动评测结果的关系

本方案与 `eval_accuracy.py` 的结果**必须并列呈现**，且要说明各自的边界：

| | 人工抽样（本方案） | 自动评测（已有） |
|---|---|---|
| 反映 | 抽中条目有多少是对的（**查准**） | 查准 + **查全** |
| 开发集（第 7 章·树） | 待判定 | 关系 F1 = 0.8312 |
| 封存集（三章） | 待判定 | 关系 F1 = 0.3029 / 0.3912 / 0.5573 |

**两个数字会不一致，这是正常的，不能取大的那个对外申报。** 抽样准确率通常**高于**
自动评测的 F1，因为抽样只测查准、不罚漏抽；而封存集的自动评测 F1 明显低于开发集，
说明跨课程泛化是主要短板。交付报告中应如实呈现这组差异并给出归因，而不是挑选有利的数字。
