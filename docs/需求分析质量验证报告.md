## 1. 验证目的、范围与依据

### 1.1 目的

1. 判断 SRS 是否具备作为**设计、开发、测试、验收共同基线**的质量水平；
2. 检查需求条目是否**可点数、可追溯、可验证**，是否存在重号、悬空引用、孤儿需求；
3. 用当前代码抽样核对，判断 SRS 写的是「需求事实」还是「过时描述」；
4. 给出**可执行的整改清单**与放行条件，而不是只给一个分数。

### 1.2 范围

| 类别 | 内容 |
|---|---|
| 纳入 | `docs/需求规格说明书.md` 全文（1820 行 / 165 KB / 984 个表格行）；`知识图谱_文档初稿 (1)/ch2.tex` 第 2 章草案；SRS 引用的证据文件（`backend/test_*.py`、`backend/eval_*.py`、`frontend-vue/tests/*.spec.ts`） |
| 纳入（抽样） | `backend/app/` 下与需求常量/分支相关的 10 个源文件（config / security / auth / member / question / practice / graph / path / fusion / vector_index） |
| 不纳入 | 系统功能验收与性能压测；真实课堂使用效果；Neo4j/SQLite 数据正确性；前端 UI 视觉质量；安全渗透测试 |
| 不纳入的理由 | 本报告回答「需求分析做得好不好」，不回答「系统跑得好不好」；后者需按 §7.1 单独出具验收记录 |

### 1.3 依据

| 依据 | 用途 |
|---|---|
| IEEE 830 需求质量八特性（正确、无歧义、完整、一致、有优先级、可验证、可修改、可追溯） | 评价维度与扣分口径 |
| ISO/IEC/IEEE 29148:2018 条款级准则（必要、实现无关、无歧义、完整、单一、可行、可验证、正确、符合） | 单条需求的质量判定 |
| `docs/需求规格说明书.md` §0.3/§0.4 自定的结构与状态标注约定 | 判断文档是否兑现了自己的承诺 |
| 仓库当前代码（`backend/`、`frontend-vue/`） | 事实核对基准（冲突时以代码为准） |
| `docs/知识抽取准确率测试报告.md`、`docs/问答测试集.md`、`docs/知识点自动标注设计.md`、`docs/题库功能说明.md`、`docs/文档级知识融合与实体消歧实施报告.md` | 指标类证据核对 |
| A10 赛题硬性指标（人工抽样准确率 ≥70%、20 题问答、四类关系等） | 完整性判断的外部约束 |

### 1.4 术语与判定口径

| 术语 | 本报告中的含义 |
|---|---|
| 条级引用 | 验收场景/追踪表里写出了具体需求编号，如 `FR-C01`、`AC-10~15` |
| 组级引用 | 只写模块字母，如 `AC-16` 的 `FR-B/C/D/E/I`；只能证明「这个模块被看了一眼」，不能证明组内每条需求被验收 |
| 已验证 | 有可追溯到本次或既有报告的实测结果；本报告不把「脚本存在」当作已验证 |
| 待验证 | 有用例/脚本但本次未执行 |
| 悬空引用 | 被引用但文档中找不到定义的需求编号 |
| 孤儿需求 | 有定义但除定义行外无任何引用 |

> **引用约定**：本文中 `§x.y`（含 `SRS §x.y`）一律指《需求规格说明书》的章节；本报告自身的章节用「第 x.y 节」表述，避免与 SRS 章节号混淆。

SRS §0.3 声明「严格对应需求结构图的八个部分」，逐项核对成立：概述、用户需求、领域与数据、规则与权限、行为与状态、质量要求、验收与验证、基线与人机协作均有独立章节且内容非空。§0.3 还逐条列出了需求结构图 3.3 的 7 项细化要求（需求清单覆盖、3~5 个代表性用例、用例 12 项模板、数据字典字段、权限矩阵、质量指标四要素、频率无数据不得编造），实测均有对应落实位置。

| 等级 | 分数 | 含义 |
|---|---|---|
| A 优秀 | ≥90 | 可直接作为基线，无需修改 |
| B+ 良好 | 85–89 | 可作基线，建议修订 |
| B 较好 | 80–84 | 可作基线，须修订后再验收 |
| C 合格 | 70–79 | 须整改后重新验证 |
| D 不合格 | <70 | 不可作为基线 |

### 4.3 评价说明

- **不要被 87.1 误导为「验收已过」**：这个分数衡量的是「需求写得怎么样」，不是「系统做得怎么样」。系统侧的验证执行率只有 7.5%（见门禁 G4）。
- **最值得肯定的三点**：① 状态与口径诚实（「已实现」不等于「已验证」，未测就标待验证）；② 规则层可执行（68 条 BR + 14 条 CR + 4 张决策表，能直接翻成测试用例）；③ 指标有原始数据（抽取/问答/标注/推荐/向量五类均有报告或 JSON）。
- **最需要修的三点**：① 编号命名空间冲突；② 验收场景与需求组错配；③ 验证闭环未执行。

## 7. 结论与放行建议

### 7.1 总体结论

**有条件通过。**

- **可以放行的部分**：SRS V1.0 的结构、条目、规则、状态、权限与数据设计足以作为**设计、开发、测试用例编写**的共同基线。它的诚实度高于同类文档：未验证就写未验证，不拿开发集指标冒充课堂效果，不把 AI 生成内容当作已确认需求。
- **不能放行的部分**：它还不能作为**验收已通过**的证据。18/20 个验收场景未执行、8/8 走查未执行，H 组需求甚至没有对得上的验收场景。
- **一句话**：**文档质量 B+，验收证据尚未闭环（执行率 7.5%），二者不能互相替代。**

### 7.2 放行条件

**必须完成（阻断验收）**

1. **QVR-01**：拆分 `G-` 命名空间（业务目标 → `BG-xx`），全文替换引用；

3. **QVR-03**：补齐 `AC-21 账户与会话`、`AC-22 教学目标监测`、`AC-23 图谱编辑一致性`，拆分 `AC-16` 的组号引用；
4. **QVR-09**：在专用环境执行全部 AC 与 8 项走查，回填「已验证（日期/环境/结果/实测值）」。

**应当完成（影响对外表述）**

5. **QVR-10**：修订 `ch2.tex` 的 7 处不一致；若章节保留叙述体，建议直接引用 SRS 编号而不是复述数值；
6. **QVR-06**：把 NFR-17/21/22/23 改写成可测目标，缺口移入 §6.4；
7. **QVR-11**：建立唯一缺陷台账（编号/状态/责任人/关闭条件），其余章节只引用编号。

**建议完成（提升可维护性）**

### D.2 复现脚本（Python 3，仓库根目录执行）

以下脚本可复现本报告的核心数字（82 / 51 / 47 / 33 / 82）：

```python
import re, pathlib

t = pathlib.Path("docs/需求规格说明书.md").read_text(encoding="utf-8")
lines = t.splitlines()
rows = re.findall(r"^\| (FR-[A-I]\d{2}) \| .+? \| (P[012]) \|", t, re.M)

def sec(a, b):
    s = next(i for i, x in enumerate(lines) if x.startswith(a))
    e = next(i for i, x in enumerate(lines[s + 1:], s + 1) if x.startswith(b))
    return "\n".join(lines[s:e])

TOK = re.compile(r"\b(FR|AC)-((?:[A-I]?\d{2})(?:[~\-–][A-I]?\d{2})?(?:[/、,，][A-I]?\d{2})*)")

def ids(text):
    out, letter = set(), None
    for m in TOK.finditer(text):
        pre = m.group(1)
        for part in re.split(r"[/、,，]", m.group(2)):
            rng = re.split(r"[~\-–]", part)
            for tok in rng:
                mm = re.fullmatch(r"([A-I])?(\d{2})", tok)
                if mm:
                    letter = mm.group(1) or letter
                    out.add(f"{pre}-{letter or ''}{int(mm.group(2)):02d}")
            if len(rng) == 2:
                a, b = [int(re.sub(r"[A-I]", "", x)) for x in rng]
                for n in range(a, b + 1):
                    out.add(f"{pre}-{letter or ''}{n:02d}")
    return out

print("FR 总数:", len(rows), "| P0:", sum(p == "P0" for _, p in rows))
for name, s in [("§2.5 用例", sec("### 2.5", "### 2.6")),
                ("§7.1 验收", sec("### 7.1", "### 7.2")),
                ("§7.3 矩阵", sec("### 7.3", "### 7.4"))]:
    print(name, "条级覆盖:", sum(f in ids(s) for f, _ in rows))
```

```
§7.1 验收 条级覆盖: 33
§7.3 矩阵 条级覆盖: 82
```
